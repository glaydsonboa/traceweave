# Promotion rules

An item is promoted to the frozen incident set only when all required evidence is present.

## Required

A promoted incident must have:

1. a concrete claim or action;
2. a primary event pointer;
3. a reproducible contradiction, execution mismatch, authority violation, or instrumentation false-state;
4. enough chronology to distinguish the original event from later interpretation.

A later self-correction or retraction strengthens the chain but is not required.

## Incident families

### F — factual or execution-state divergence

Used when a concrete factual/verification claim is contradicted by a stronger source, or when narrated execution diverges from demonstrated execution.

### U — authority or scope violation

Used when an action is demonstrably outside an explicit governing instruction or authorization boundary.

This category does not require damage. The violation can be procedural.

### I — instrumentation false-state

Used when a status or instrument reports a state that stronger underlying evidence shows to be false or structurally unobservable.

## Not sufficient for promotion

The following alone are not enough:

- a suspicious sentence;
- a disagreement in interpretation;
- a later document summarizing an event;
- a phrase such as "I lied";
- a model answer that is simply wrong;
- a candidate found by keyword search;
- an inference about motive.

## Alternative explanations

Each exemplar case records plausible narrower explanations.

The purpose is not to eliminate all benign explanations. It is to establish the smallest claim that the evidence supports.

Example:

- a search intermediary may have generated an incorrect statistic;
- that does not prove the model invented the statistic internally;
- but if the agent attaches that statistic to a source it did not verify and later the source is shown not to contain it, the unsupported source attribution is still demonstrable.
