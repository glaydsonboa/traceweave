# Limitations

1. This is a longitudinal forensic case study, not a representative statistical sample.

2. The promoted incident count must not be converted into a population failure rate. The initial search-candidate set is not a denominator.

3. Retrospective phrases such as "I lied" or equivalent are textual self-classifications. They are not evidence of subjective intent.

4. The strongest claims are event-specific. A demonstrated divergence in one event does not imply that all self-reports in the session or model family are unreliable.

5. Three late sessions in the frozen candidate are evidence class B because the final original RAW JSONL bytes did not survive the workstation format in the available backups. They are kept separate from class-A primary-raw sessions.

6. The Git provenance material demonstrates repository history, file membership and observed blob continuity where available. It does not constitute a cryptographic signature by the model vendor.

7. Commit authorship shown by GitHub belongs to the repository account. A `Co-Authored-By` line naming a model is commit-message metadata, not vendor authentication.

8. July reconstruction/corroboration has a different evidence class from the August–September raw corpus.

9. Sanitization changes public transcript bytes. Public hashes verify the sanitized artifact; source hashes and redaction manifests establish the relationship to preserved inputs.

10. The three exemplar cases were selected for methodological diversity, not because they are statistically "the worst" incidents.

11. A case can establish that a claim was unsupported without establishing the opposite factual state. For example, proving that an instrument could not observe Notion does not prove that Notion was actually called; it proves that "zero calls" was not established by that instrument.
