# TraceTrack — local page over agent logs

One page, served on `127.0.0.1`, that shows what each coding agent on this machine did and runs new jobs behind a
PROMPT_ID gate.

```bash
pip install -e .
traceweave tracetrack --workdir C:\path\to\project --repo C:\path\to\project
# → TraceTrack on http://127.0.0.1:7317
```

## What it shows

- **TraceTrack pane** (right; collapses with × and comes back from the chip or the rail): the job queue, then the
  session logs found on this machine — Claude Code (`~/.claude/projects`), Codex (`~/.codex/sessions`) and DeepSeek
  (Claude Code sessions whose assistant messages name a DeepSeek model).
- **A session**: path, SHA-256 and size of the log; prompts, tool calls, events; first and last prompt typed by the
  person (harness injections such as `AGENTS.md` are left out); last actions; last agent answer; the
  `traceweave claims` findings. Nothing is generated by a model: every field is read from the log.
- **A job**: status, prompt, the run output line by line, and, when it ends, the findings on its own transcript.

## Job gate

1. Write the prompt and pick the executor (Claude, Codex, DeepSeek).
2. The server creates a PROMPT_ID `TW-<date>-<time>-<8 random characters>` and sends it **outside the page**: by SMS
   when Twilio is configured, otherwise to the terminal running the server. The page never shows the full ID.
3. Type the PROMPT_ID back. Spaces and case do not matter. It expires in 10 minutes; three wrong tries lock the job.
4. The job runs in `--workdir`: `claude -p … --output-format stream-json --verbose`, `codex exec --json …`, or Claude
   Code pointed at DeepSeek.

Every job event (created, rejected, authorized, done, failed, locked, expired) is appended to
`~/.traceweave/tracetrack/jobs.jsonl`.

## Configuration (environment variables)

| Variable | Use |
|---|---|
| `DEEPSEEK_API_KEY` | enables the DeepSeek executor (`ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic`) |
| `TRACETRACK_DEEPSEEK_MODEL`, `TRACETRACK_DEEPSEEK_URL` | optional model and endpoint for DeepSeek |
| `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_FROM`, `TRACETRACK_SMS_TO` | SMS delivery of the PROMPT_ID |
| `TRACETRACK_CMD_<EXECUTOR>` | JSON list replacing an executor's command (`{prompt}` placeholder); used by the tests |
| `TRACETRACK_CLAUDE_ROOT`, `TRACETRACK_CODEX_ROOT` | other log locations |

## Safety

- Binds to `127.0.0.1` only; any other `Host` header gets 403 (DNS rebinding).
- POST needs a JSON body and, when the browser sends `Origin`, a local origin (cross-site requests get 403).
- Sessions are opened by an ID from the server's own listing, never by a path from the request.
- Jobs run with the CLI's default permissions; the page adds no permission flag.

## Start it so you can see the PROMPT_ID

```powershell
pwsh -NoExit -File tools/start-tracetrack.ps1 [-Workdir C:\path\to\project] [-Port 7317]
```

The PROMPT_ID is printed in the window that runs the server. A server started in the background (by an agent,
a service) prints it where nobody looks: the job then expires. This happened on 11 Oct 2026 (job `cd689d60`).
The script also wires DeepSeek through `tools/run-deepseek-job.ps1`, which reads the key from the Worion Vault
into its own process only.

## Restart

The queue is rebuilt from `jobs.jsonl`. The PROMPT_ID is never written to disk, so a job still waiting for it
comes back `expired`; a job that was running comes back `failed` ("server restarted during the run").

## Limits

- Local only. Reaching it from a phone needs a tunnel in front of it, and then the Host check and the gate are the
  only protection: put authentication on the tunnel before exposing it.
- SMS delivery is written against the Twilio REST API and **has not been tested** with a real account.
- Measured end to end on 11 Oct 2026, one job per executor, prompt "Responda apenas com a palavra OK": Claude
  (result "OK"), Codex (`codex exec --json`, result "OK"), DeepSeek V4 Pro through `run-deepseek-job.ps1`
  (result "OK"). Each transcript was found and audited, with no findings. Trivial prompts: this shows the
  plumbing works, not that the audit catches anything in a real job.
