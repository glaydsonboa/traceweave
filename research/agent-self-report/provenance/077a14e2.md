# Provenance case — 077a14e2

**Session:** `077a14e2-ef9a-4f4e-8095-07ffc13e0cce`

This is not presented as one of the exemplar failure cases.

Its purpose is different: demonstrate that a session transcript and its surrounding closure artifacts existed in Git history before the later public research publication.

The earlier public index is [Issue #3](https://github.com/glaydsonboa/traceweave/issues/3).

The commit message records the transcript as a hook-produced session artifact and includes a `Co-Authored-By` line naming Claude.

That line is metadata, not a vendor signature.

## What this supports

The evidence supports the narrower statement:

> Claude Code, operating the user's repository, participated in a workflow that produced and versioned this session transcript, and the artifact has observable Git genealogy predating this public research case.

It also supports continuity of the observed transcript blob from the later hook update into the archival migration.

## What this does not support

This case does **not** claim:

- that Anthropic cryptographically signed the transcript;
- that the `Co-Authored-By` trailer authenticates a vendor;
- that every statement inside the transcript is true because the transcript is historically genuine;
- that a later public mirror is itself the original artifact.

GitHub reports the commits as authored/committed by the repository account.

The provenance claim is about artifact genealogy, not vendor attestation.

## Why this matters

A later researcher can write a narrative today. That alone proves little about what existed earlier.

A pre-existing repository history provides an independent chronology anchor for the artifact.

That is why this session is used as a chain-of-custody demonstration rather than as another incident.
